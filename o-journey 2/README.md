# O! Journey — Travel Architect MVP

Рабочая интерактивная браузерная демоверсия для трека «О!дин запрос» O! Hackathon 2026.

## Запуск

Без установки зависимостей:

```bash
python3 -m http.server 8080
```

Открыть `http://localhost:8080`.

Также можно открыть `index.html` напрямую в браузере. Для изображений нужен интернет; интерфейс и расчёты работают без него.

## Персонализация впечатлений (итерация 2)

- Три явных режима рекомендаций: «Хочу похожее», «Баланс», «Хочу совершенно новое».
- Оценки конкретных мест: понравилось / не понравилось / хочу посетить, текстовые заметки.
- Оценки отелей: понравилось / сохранить / не подходит, текстовые причины отказа.
- Хранение оценок в localStorage и применение сигналов к ранжированию направлений.
- При выборе направления по умолчанию избегаем жилья, отмеченного как неподходящее; при негативной оценке текущего варианта переключаем на допустимый, если он есть.
- Это прототип предпочтений: оценки отелей основаны на демонстрационных карточках и не являются отзывами о реальных объектах.

## Что реализовано

- Обработка текстового запроса простыми правилами и извлечение части параметров.
- 8 разнообразных направлений: гастрономия, культура, море, архитектура, природные маршруты и т.д.
- Ранжирование направлений по предпочтениям, бюджету и истории посещений.
- 3 альтернативных варианта жилья на каждое направление.
- 3 экскурсии на каждое направление, включение/исключение из корзины.
- Детализированная смета, изменение состава корзины и проверка лимита.
- Планировщик по дням (пока иллюстративные слоты).
- My World — учёт посещённых направлений и предпочтений через localStorage.
- Загрузка референсов (без автоматического распознавания; пока в памяти вкладки).
- Имитация оформления заказа с понятным предупреждением.
- Адаптивная версия для мобильного экрана.

## Ограничения, которые необходимо устранить до финальной защиты

- Все суммы, названия гостиниц и экскурсий — **синтетические демонстрационные данные**, не подтверждённые предложения.
- НЕТ подключения к реальным API цен и доступности.
- НЕТ LLM и реального распознавания изображений (текстовый запрос разбирает только набор эвристик).
- Планировщик не проверяет транспортные и временные стыковки, даты и сезонные условия.
- Мультистрановая маршрутизация в коде отсутствует — её необходимо реализовать.
- Для не-СПб города отправления транспортные цены должны пересчитываться, сейчас этого нет.
- Цена жилья предполагает 2 гостей на один номер, вне этой конфигурации требуется формула по вместимости.

## План следующей итерации

1. Бэкенд API и структурированная схема `Trip -> Segments -> Offers -> Cart`.
2. LLM-парсер запроса с валидацией (включая негативные критерии и намерение группы), tool calling.
3. Реальный каталожный источник отелей, транспорта и экскурсий, с `source`, `retrievedAt`, `confidence` у каждой цены.
4. Constraint solver: время переездов, ночи, заезд/выезд, вместимость, бюджет, визовые требования.
5. Multi-city/multi-country optimizer, альтернатива со stopover, сравнение качества сценариев.
6. Vision-модуль для фото и мудбордов.
7. Регрессионные тесты на неожиданных запросах жюри, метрики успешности и ошибок.

## Итерация 3 — 28 октября 2026

- Добавлены месяц поездки и число студентов (0–число участников), включая проверку допустимого диапазона.
- Сезонные предупреждения по восьми направлениям: это **иллюстративные сезонные сведения**, не актуальный прогноз. Для продакшена требуется Open-Meteo API и правила допустимых сроков прогноза.
- Льготы не уменьшают цену до подтверждения источника, права участника, даты и применимости тарифа.
- Изменение состава, дат, жилья и экскурсий сбрасывает статус демо-бронирования.
- Оставлено содержательное сообщение в HTML на случай блокировки JavaScript в мобильном превью.
- Пройден smoke-test интерфейсных функций через Node.js VM и `node --check`; браузерный E2E пока не выполнен.

**Следующий рубеж:** полноценная веб-сборка с реальным backend, хранилищем PostgreSQL и адаптерами API. Нельзя выдавать этот демо-каталог за актуальные цены и наличие.

## Backend verification API (iteration 4)

Run from project root:

```bash
python -m pip install -r backend/requirements.txt
python -m uvicorn backend.app:app --reload --port 8000
```

Open http://127.0.0.1:8000 (not `index.html` via iOS file preview). API docs: http://127.0.0.1:8000/docs. The weather panel fetches Open-Meteo from the backend. For dates >15 days away, it shows a small historical day-of-year sample **not a forecast**. The app does not claim to quote real hotels, flights, or activities. `/api/quote` is a server-side arithmetic and eligibility guard for supplied quotes, not a live price verifier. `source_type=verified` is a trusted-upstream field that must only be set by a real provider integration, never by an untrusted client in production.

Tests: `python -m pytest -q tests/test_api.py`.

For GitHub, copy the whole project folder into a development branch of `ostrovok-hackathon-2026/oops` after access is granted. Do not commit `.env`, tokens, or personal data. The prototype front end and `backend/` can run together through FastAPI; this is not a deployed public app.
